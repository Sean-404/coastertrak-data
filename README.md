# coastertrak-data

Data ingestion, processing, validation, and quality-control pipeline for [CoasterTrak](https://github.com/Sean-404/CoasterTrak).

This is a **standalone repository**. It does not write to CoasterTrak’s production DB tables. It reads the live catalog for quality analysis and uploads report artifacts to Supabase Storage for the admin UI.

## Two roles

1. **Live catalog quality (production path)** — `analyze:supabase` → optional `ai:review` → `publish`  
   Used by CoasterTrak CI (`catalog-quality.yml`, post-Wikidata refresh) and locally via:
   ```bash
   # from CoasterTrak, with this repo as a sibling at ../coastertrak-data
   npm run data:catalog-quality
   ```
2. **Offline Wikidata pipeline** — ingest → process → validate → export  
   Builds a reproducible canonical dataset under `data/` for research / future import work.

## Philosophy

Do **not** scrape Wikidata and copy it directly into CoasterTrak. Instead:

```
Wikidata / external sources / live Supabase catalog
        ↓
   Raw or read-only export
        ↓
   Normalisation + validation
        ↓
   Review queue (+ optional AI)
        ↓
   Quality reports → Supabase Storage (admin UI)
```

The offline pipeline is **reproducible** and **deterministic**. Raw Wikidata snapshots are never overwritten by processing logic.

## Architecture

```
coastertrak-data/
├── data/
│   ├── raw/          # Immutable source snapshots (gitignored)
│   ├── processed/    # Mapped canonical entities per run
│   ├── review/       # Human review queue (generated by validate / analyze)
│   ├── overrides/    # Manual corrections (survive re-imports)
│   ├── reports/      # Validation reports per run
│   └── output/       # Final canonical export (Wikidata path)
├── fixtures/         # Committed test data
└── src/
    ├── canonical/    # Zod schemas + TypeScript types
    ├── sources/      # Source adapters (Wikidata + Supabase)
    ├── normalize/    # Name, date, status, coordinate normalisation
    ├── validate/     # Quality rules and reporting
    ├── matching/     # Duplicate detection
    ├── pipeline/     # process, validate, analyze, publish
    ├── confidence/   # Quality scoring
    ├── overrides/    # Override schemas
    └── export/       # CoasterTrak export mapping
```

## CoasterTrak integration (live)

Clone as a **sibling** of CoasterTrak:

```text
CoasterTrak/
coastertrak-data/
```

Or set `COASTERTRAK_DATA_DIR` to this repo’s path.

### Setup for analyze / publish

```bash
cd coastertrak-data
npm install
cp .env.example .env.local
# Copy NEXT_PUBLIC_SUPABASE_URL + SUPABASE_SERVICE_ROLE_KEY from CoasterTrak/.env.local
# Optional: AI_GATEWAY_API_KEY for ai:review
```

Service role is used for catalog **reads** and Storage **uploads** only — this CLI does not mutate parks/coasters rows.

### Commands (quality path)

| Command | Description |
|---------|-------------|
| `npm run analyze:supabase` | Read live Supabase catalog, validate, write `data/processed/supabase/{runId}/` + review queue |
| `npm run ai:review` | Optional AI pass over the review queue |
| `npm run publish` | Upload `meta.json` / `report.json` / queue / bundle to Storage (`catalog/coastertrak-data/latest`) |

`analyze:supabase` writes artifacts even when findings exist. Pass `--strict` to exit non-zero on validation errors (CI leaves this off so publish still runs).

From CoasterTrak:

```bash
npm run data:catalog-quality
# or: npm run data:catalog-quality -- --skip-ai
```

### Storage contract

Published `meta.json` includes `version`, `generatedAt`, `source`, `runId`, `parkCount`, `coasterCount` for the CoasterTrak admin catalog page.

## Offline Wikidata pipeline

### Setup

```bash
cd coastertrak-data
npm install
cp .env.example .env.local
# optional for live ingest: WIKIDATA_USER_AGENT
```

### Commands

| Command | Description |
|---------|-------------|
| `npm run ingest` | Copy fixtures → `data/raw/` (default) |
| `npm run ingest -- --live` | Query Wikidata live (use `--max-rows` for safety) |
| `npm run process` | Map raw → canonical, apply overrides → `data/processed/` |
| `npm run validate` | Validate processed catalog, write reports + review queue |
| `npm run validate -- --fixtures` | Validate committed fixture JSON only |
| `npm run report` | Print quality report to stdout |
| `npm run export` | Export to `data/output/` |
| `npm run pipeline` | Full run: ingest → process → validate → export |
| `npm test` | Run Vitest unit tests |
| `npm run typecheck` | TypeScript check |
| `npm run lint` | ESLint |

### Relationship to CoasterTrak’s in-repo pipeline

CoasterTrak still owns the **sync / publish-to-DB** path under `src/lib/coastertrak-data/` and `npm run data:*`. This repo owns **quality analysis + admin report publish**. Prefer not to diverge rules without updating both sides.

## Canonical schema notes

Internal storage uses **ISO 3166-1 alpha-2** country codes. Parks whose DB country label cannot be mapped are kept with `ZZ` and `needsReview` (they are no longer dropped, which previously orphaned coasters).

Historical coasters remain in the dataset with appropriate status — they are not deleted.

## Design principles

1. Raw data is immutable
2. Processing is deterministic
3. Production CoasterTrak DB rows are never modified by this CLI
4. Ambiguous entities are flagged, not silently merged
5. Manual overrides are separate from source data
6. Every important value has provenance
7. Validation catches errors without destroying unusual records
8. Architecture supports additional sources
9. Keep it simple
10. Correctness over quantity

## Testing

```bash
npm test
```

Tests use committed fixtures in `fixtures/` — never production data as mutable fixtures.
